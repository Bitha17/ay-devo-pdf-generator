📋 .txt / .docx format guide

Either file type works, using the same field-label structure (THEME:, Ayat Bacaan:, M1:, Key Message:, Segment 1:/2:, Aplikasi:, M3:/M4:) shown below.

Header (before the first line of underscores)

Week 4 Jan 2026 - Kabar Baik untuk Orang Miskin
25-31 Januari 2026
________________

The title (used if you don't override it below) is whatever follows the first " - " on line 1.

Each day

Minggu, 25 Januari 2026 - JOL
THEME: Kasih Yesus bagi Mereka yang Dianggap Tak Berhak
Ayat Bacaan: Matius 15:21-28
M1: Berdoalah kepada Allah agar kamu memahami pesan Allah hari ini.
Key Message: Yesus datang bukan hanya untuk orang yang dianggap berhak…
Pertanyaan Perenungan Ayat:
1. Mengapa perempuan Kanaan itu tetap datang kepada Yesus?
2. Apa yang Yesus lihat dari iman perempuan tersebut?
________________

M2: DEVOTION
Segment 1: [Konteks / Penjelasan Ayat]
Dalam peristiwa ini, Yesus bertemu dengan seorang perempuan Kanaan…
Segment 2: [Gospel Connection / Firman Kristus]
Melalui peristiwa ini, Yesus menunjukkan bahwa kasih dan keselamatan…
Aplikasi:
1. Pernahkah kamu merasa tidak layak datang kepada Tuhan?
2. Apakah kamu masih membatasi kasih Tuhan hanya untuk orang tertentu?
________________

M3: Yang saya akan lakukan setelah menerima Firman Kristus ini adalah…
Saya mau datang kepada Yesus dengan iman…
M4: Share saat teduh hari ini ke pembina atau kompakmu!
________________

Day header format: <Hari>, <tanggal> - <inisial> (day name in Indonesian: Minggu/Senin/Selasa/Rabu/Kamis/Jumat/Sabtu). Repeat the block above once per day, each starting with its own day header line and separated by a line of underscores. M2: is written by convention but not read by the parser.

Inline formatting

In a .txt file, any field can contain <b>bold</b>, <i>italic</i>, or <br> — they render in both the PDF and the web view.

In a .docx file, skip the tags — just select text and use Word's normal Bold/Italic formatting. It only carries through for Segment 1 (Konteks) and Segment 2 (Firman Kristus) — every other field (theme, questions, aplikasi, M1/M3/M4, etc.) is kept plain even if formatted, since those are short structured lines where it isn't meaningful. Keep the field labels themselves (THEME:, Segment 1:, day headers, etc.) as plain, unformatted text too, since those are matched literally.
